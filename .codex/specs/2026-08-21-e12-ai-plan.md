# E12 · AI — แผนสถาปัตยกรรม + เฟส (planning)

วันที่: 2026-08-21 · Epic: FAM-E12 · สถานะ: **ร่างแผน (รอเจ้าของเลือกฟีเจอร์แรก)**

## 1) เป้าหมาย + ข้อจำกัด (จาก epic)
เดินสาย AI ฝั่ง server ให้พร้อมเปิดใช้ แล้วเลือกฟีเจอร์แรก · ไอเดีย: ผู้ช่วยวิเคราะห์ (ถามไทย) · ช่วยนำเข้า .xls · ร่างข้อความติดตามลูกค้า

**ข้อจำกัดตายตัว (ห้ามพลาด):**
- AI เรียกข้อมูลผ่าน **ชั้นเดียวกับ user จริง** — เคารพ RLS + money-strip · **ห้าม AI เห็น money-field ที่ role นั้นไม่มีสิทธิ์**
- API key ฝั่ง server เท่านั้น · จำกัด/บันทึกการเรียก (rate-limit + log)

## 2) สถาปัตยกรรม
- **SDK/โมเดล:** `@anthropic-ai/sdk` (official) + โมเดล **`claude-opus-5`** เป็นค่าเริ่มต้น · งานถูก/ปริมาณมาก (จัดหมวด/ดึงข้อมูล) ใช้ `claude-haiku-4-5` ได้ · streaming (SSE) สำหรับแชต
  - ทางเลือก: Vercel AI SDK (`ai` + `@ai-sdk/anthropic` + `useChat`) DX ดีสำหรับแชต Next.js แต่เป็น wrapper ของบุคคลที่สาม — **ถามเจ้าของก่อนเลือก** (epic เขียน "Vercel AI SDK" ไว้)
- **Route:** `app/api/ai/<feature>/route.ts` — server เท่านั้น · key จาก `process.env.ANTHROPIC_API_KEY` (ไม่มี NEXT_PUBLIC) · gate ด้วย `getCurrentUser()` · เปิด/ปิดด้วย env flag `AI_ENABLED`

## 3) 🔒 ชั้นความปลอดภัยข้อมูล (หัวใจของ E12)
> **AI ไม่แตะ DB ตรง ๆ เด็ดขาด** — ข้อมูลทุกชิ้นที่ป้อนให้โมเดลต้องผ่านชั้น user จริงก่อน

- ดึงข้อมูลด้วย **`createServerSupabase()`** (เซสชัน user → RLS แยกสาขาบังคับที่ DB) · **ห้ามใช้ `createAdminSupabase()`** (service_role ข้าม RLS) ในโค้ด AI
- money-strip ด้วย `canSeeMoney()` + `stripMoneyFields()` ก่อนส่งเข้า prompt — role ที่ไม่มีสิทธิ์ money จะไม่มีตัวเลขเงินใน context เลย
- **ผู้ช่วยแบบ tool-use:** tool ที่ query ข้อมูลต้องเรียกผ่านเซสชัน user + money-strip เสมอ → แม้โมเดลถูกหลอก (prompt injection) RLS ที่ DB ก็เป็นด่านสุดท้าย
- ถือข้อมูลจาก DB/ผู้ใช้เป็น **ข้อมูล ไม่ใช่คำสั่ง** · system prompt ตายตัว · log: user, feature, tokens, เวลา · rate-limit ต่อ user

## 4) เฟส (แตกเป็น ticket)
- **FAM-1065 · Phase 0 infra** — ติดตั้ง SDK + helper: `lib/ai/client.ts` (โมเดล/คีย์), `lib/ai/guard.ts` (auth + rate-limit + log), route ตัวอย่าง `/api/ai/ping` (ปิดด้วย `AI_ENABLED=false` เป็นค่าเริ่มต้น) · .env.example: `ANTHROPIC_API_KEY`, `AI_ENABLED` · **= epic "Done when"**
- **FAM-1066 · Phase 1 (แนะนำเป็นตัวแรก): ร่างข้อความติดตามลูกค้า** — input = context ดีล/ลูกค้าที่ authorized แล้ว → ร่างข้อความไทยสุภาพ · UI: ปุ่ม "ร่างข้อความ (AI)" ในแผงดีล/งานติดตาม (ต่อ E08/E10) · **contained, ไม่มี open-ended data access → money-strip ง่าย, เสี่ยงต่ำสุด**
- **FAM-1067 · Phase 2: ผู้ช่วยวิเคราะห์ (เรือธง)** — ถามไทย ("เดือนนี้ขายกี่คัน", "รถค้างนานสุด") ตอบจากข้อมูล **ผ่าน tool-use ที่เคารพ RLS/money-strip** · ยากสุด — ทำหลัง infra + pattern นิ่ง
- **FAM-1068 · Phase 3: ช่วยนำเข้า .xls** — parse ไฟล์ Yamaha export เละ ๆ → แถวมีโครงสร้าง (contained, ประมวลไฟล์อัปโหลด ไม่แตะ live data)

## 5) ต้นทุน (คร่าว)
opus-5 = $5/$25 ต่อ 1M (input/output) · ร่างข้อความ ~1–2k tokens/ครั้ง ≈ เศษสตางค์ · ผู้ช่วยวิเคราะห์แพงกว่า (tool-use หลายรอบ) — ตั้ง rate-limit + budget cap ต่อ user/วัน · prompt caching ลดค่า context ซ้ำ
