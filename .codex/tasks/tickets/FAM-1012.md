## เป้าหมาย
หน้าจัดการใบงานซ่อม — รายการงาน กรองตามสถานะ/วันที่ ดูรายละเอียด (ค่าแรง/อะไหล่/ยอดชำระ)
และ**เลื่อนสถานะ**ตามสเตตแมชชีน (รับเข้า → กำลังซ่อม → รออะไหล่ → เสร็จ → ส่งมอบแล้ว)

## ที่มา
- data model: `service_job` (status flow ในคอลัมน์) + `service_job_line` (labor|part) — RLS branch-scoped อยู่แล้ว
- docs/04: สถานะเป็น**ตัวบอก** + ปุ่มเขียนตรง ๆ ว่าจะไปขั้นไหน ("ไป: … →") ไม่ใช่คัมบัง (ลบคัมบังไปแล้ว v1.15)
- R1 (`.codex/specs/revision-1-client-feedback.md` §ศูนย์ซ่อม): **ค่าแรง → ยอดชำระ** · เพิ่ม **ตัวเลือกวันที่**

## ขอบเขต (in)
- Route `/service` (SSR ผ่าน RLS): join ลูกค้า/รถ(รุ่น·สี หรือ เลขเครื่องรถนอก)/ช่าง/รายการ
- สรุปตามสถานะ (นับต่อสถานะ กดกรองได้) + FilterBar: ค้นหา + **ตัวเลือกวันที่ (ตั้งแต่)** + ชิปสถานะ
- ตาราง (มือถือ = การ์ด): เลขงาน/ลูกค้า · รถ · ประเภท · สถานะ · วันที่รับ · **ยอดชำระ**
- Drawer รายละเอียด: รถ/เลขเครื่อง/ไมล์/ประเภท/ช่าง/อาการ · รายการ (ค่าแรง/อะไหล่) · สรุป **ค่าแรง/ค่าอะไหล่/ยอดชำระ**
- **เลื่อนสถานะ**: ปุ่ม "ไป: <ถัดไป> →" → `advanceStatus` (ตรวจสิทธิ์ + ตรวจทางเดินที่อนุญาต + compare-and-swap กันเลื่อนซ้ำ + ตั้ง started_at/finished_at)
- helper บริสุทธิ์ + tests: `nextStatuses`/`canTransition`/`isTerminal`/`statusVariant`, `filterJobs`/`statusCounts`/`openJobCount`/`canManageService`
- `/dev/service` preview (4 สถานะ + mock) + verify desktop/mobile ไม่มี h-scroll
