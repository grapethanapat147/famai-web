# FAM-1033 · หน้าเงินเดือนและ OT (payroll)

**Epic:** FAM-E09 (บัญชีและพนักงาน)
**สถานะ:** Done (read-only — verify ได้เต็ม) — ปิดกลุ่มบัญชีและพนักงาน
**สาขา:** `feat/payroll-screen`

## เป้าหมาย
สลิปเงินเดือนต่องวด (เดือน) — คำนวณสด: ฐาน + OT + คอมมิชชั่น − ประกันสังคม = สุทธิ

## ที่มา
- data model: `employee.base_salary` + `attendance.ot_minutes` + `sale.gross_profit` (คอม) · schema มี `payroll_period`/`payroll_line`/`commission_rule` (ยังไม่ generate)
- ค่าจาก `app_setting`: ot_rate, ssn_pct, ssn_cap, commission_pct (หน้าตั้งค่า FAM-1018)
- roles: admin/manager/hr/acct · **read-only** → verify เต็ม

## ขอบเขต (in)
- Route `/payroll?month=YYYY-MM` (SSR ผ่าน RLS): พนักงาน active + OT รวมในงวด + กำไรของ salesperson ในงวด
- **คำนวณสด** `computePayslip`: OT = (ฐาน÷240) × ชม.OT × เรต · คอม = กำไร × % · ปกส. = min(ฐาน×%, เพดาน)
- **money guard**: ทั้งหน้าเป็นข้อมูลเงินเดือน → ไม่มีสิทธิ์ money = ไม่ส่งตัวเลขไป client เลย (zero) + โชว์ —
- month selector (เปลี่ยนงวด → re-fetch ผ่าน `?month=`) + ค้นหา + ตารางสลิป + แถวรวม
- **ส่งออก CSV** (BOM) + **พิมพ์** (print: utilities)
- helper บริสุทธิ์ + tests (6 เคส): computePayslip (ตัวอย่างจริง 23,188)/monthRange (อธิกสุรทิน)/payrollTotals/canViewPayroll
- `/dev/payroll` preview + verify desktop/mobile ไม่มี h-scroll

## ขอบเขต (out / ตามมา)
- ปิดงวด/จ่าย (payroll_period status + บันทึก payroll_line) · สลิปรายคน (PDF ให้พนักงาน)
- เบี้ยเลี้ยง/หักสาย/ภาษี · คอมตาม `commission_rule` (per_unit/pct_of_gp/pct_of_revenue) แทน commission_pct รวม
- prorate ฐานตามวันเข้างานจริง · ส่วนนายจ้าง ปกส. (employer_ssn สำหรับรายงาน)
