## ปัญหา
`clockIn` / `clockOut` ประทับเวลาด้วย `new Date()` ของเซิร์ฟเวอร์แอป และเขียนแถวโดยตรง
กฎโปรเจกต์ (CLAUDE.md ข้อ 4 · security-checklist §9i) ให้เวลามาจากฐานข้อมูลผ่าน RPC
เพื่อให้เวลาที่ใช้คิดเงินเดือนมาจากแหล่งเดียวที่โกงไม่ได้ และตรวจ "ลงเวลาแล้วหรือยัง" ในทรานแซกชันเดียวกับการเขียน

## ทำไมไม่ใช้ `punch_clock()` เดิม (migration 12) ตามที่รายการเสนอ
RPC เดิมบังคับรูป+พิกัดทุกครั้ง (แอปมีตั้งค่าเซลฟี่ต่อบริษัท) และเขียนคอลัมน์ที่แอปไม่ได้อ่าน (`check_in_dist_m`, `check_in_photo_url`)
ถ้าสลับไปใช้ พฤติกรรมหน้าลงเวลาจะเปลี่ยนโดยไม่ตั้งใจ จึงทำ RPC คู่ใหม่ที่รับผลการตรวจจาก server action แล้วประทับ `now()` ของ DB

## ทำอะไรบ้าง — migration 36
- `punch_in(lat, lng, distance_m, site_id, site_name, selfie_path, work_start)` — พนักงานจาก `auth.uid()` (ลงแทนคนอื่นไม่ได้)
  วันตามเวลาไทย · คิดสายจาก `work_start` · ล็อกแถว + กันลงซ้ำ · upsert ทับแถว ลา/ขาด ที่ยังไม่มีเวลาเข้า
- `punch_out(work_end, ot_step)` — ล็อกแถววันนี้ · ต้องมีเวลาเข้าและยังไม่ออก · คิดชั่วโมงงาน + OT
- **สูตรตรงกับ `lib/hr/time.ts` ทุกบรรทัด** (`lateMinutes` / `workMinutes` / `otMinutes` — OT นับจาก max(เลิกงาน, เข้า) ปัดลงช่วงละ 30 นาที)
  ฟังก์ชัน TS ยังอยู่พร้อมเทส 11 ชุด ใช้แสดงผล/พรีวิว · SQL เป็นตัวเขียนจริง

server action ยังทำหน้าที่ตรวจ geofence/จุดลงเวลา/เซลฟี่ เหมือนเดิม แล้วส่งผลให้ RPC — ไม่มีการเขียน `attendance` ตรงจากแอปอีก
