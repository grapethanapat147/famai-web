## ช่องโหว่ของตัวเองที่เจอตอนทำ
FAM-1127 สร้างเงินค้างรับจากขายส่งโดย **ไม่มีทางโยงกลับไปหาบิล** (`sale_id` เป็น null เฉย ๆ)
พอจะยกเลิกบิล ก็หาเงินค้างรับของบิลนั้นไม่เจอ → migration 35 เติม `receivable.wholesale_order_id`
และแก้ `sell_wholesale` ให้เขียนค่านี้ด้วย

ผลพลอยได้: หน้ารอรับเงินเดิมสมมติว่าทุกแถวมี `sale` — พอแก้ type ให้ตรงความจริงก็เจอทันที
ตอนนี้แถวขายส่งโชว์ **ชื่อร้านค้า** เป็นผู้จ่าย และโชว์ "บิลขายส่ง FMG-WHOLESALE-…" แทนช่องรถที่ว่างเปล่า

## ใบกำกับภาษีของบิลขายส่ง
- `document.wholesale_order_id` (เดิมผูกได้แค่ `sale` / `service_job`)
- ผู้ซื้อ = ร้านค้า · ยอด = ยอดรวมทั้งบิล · รายการ = รุ่นรถทุกคันพร้อมเลขเครื่อง
- เลขเอกสารดึงจากชุด **TAXINV เดียวกับขายปลีก** (เล่มใบกำกับเป็นชุดเดียว)
- **ยังไม่กรอกเลขผู้เสียภาษีของร้านค้า = ออกไม่ได้** (เหมือนกฎของไฟแนนซ์ใน FAM-1126)
- unique index กันออกซ้ำ

## ยกเลิกบิล — RPC `void_wholesale_order`
ทำ 3 อย่างในทรานแซกชันเดียว: **คืนรถเข้าสต๊อก** + ล้างเงินค้างรับที่ยังไม่ได้รับเงิน + ปิดบิลพร้อมเหตุผล

กฎที่บังคับฝั่ง DB:
- **ออกเอกสารไปแล้วยกเลิกบิลไม่ได้** ต้องยกเลิกเอกสารก่อน ไม่งั้นจะมีใบกำกับของบิลที่ไม่มีอยู่จริง
- คืนสต๊อกเฉพาะคันที่ยัง `sold` — ถ้าคันนั้นถูกขายต่อไปแล้วไม่ไปแตะ
- ล้างเฉพาะเงินค้างรับที่ **ยังไม่มีการรับเงิน** — รับเงินไปแล้วต้องให้คนตัดสินใจเอง
- ยกเลิกได้เฉพาะ admin/manager · ต้องระบุเหตุผล
