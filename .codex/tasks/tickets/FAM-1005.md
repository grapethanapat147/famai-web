## FAM-1005: Auth — login & session

Status: Backlog
Priority: High
Epic: FAM-E03
Refs: docs/02-architecture.md §5 · Spec §8, §12.1 · security-checklist.md

### Summary
ล็อกอินด้วย Supabase Auth (bcrypt, ห้ามเขียน hash เอง), session ฝั่งเซิร์ฟเวอร์ (cookie), และดึงสิทธิ์ผู้ใช้ (role/branch/perms จาก `app_user`/`role`/`app_user_branch`) เข้า context ที่ server ใช้ตัดสิน — เตรียม JWT claims/หรือ server lookup ให้ RLS + เมนู + money-strip ใช้ต่อ

### Acceptance Criteria
- หน้า login ทำงาน, session ปลอดภัย (httpOnly cookie), logout ได้
- ไม่มีบัญชีที่ใช้ร่วมกันหลายคน (1 user 1 บัญชี) — ตามเกณฑ์ตรวจรับ Spec §12.1
- server รู้ perms/branch ของ user ปัจจุบันผ่าน helper เดียว (`getCurrentUser()`), unknown role → fail closed (ไม่มีสิทธิ์)
- รหัสผ่านถูก hash โดย Supabase (ยืนยันไม่มีการเก็บ plain ที่ใดเลย)

### Validation
- test: login/logout, session หมดอายุ, ผู้ใช้ inactive เข้าไม่ได้
- test: `getCurrentUser()` คืน perms ถูกตาม role seed (9 บทบาท)

### Notes
- ทดสอบล็อกอินบัญชีจริงยังทำไม่ได้จนกว่ามีรหัสผู้ใช้ (handoff §8) — เตรียม seed/test user
