## FAM-1005: Auth — login & session

Status: Done
Priority: High
Epic: FAM-E03
Refs: docs/02-architecture.md §5 · Spec §8, §12.1 · security-checklist.md

### Summary
ล็อกอินด้วย Supabase Auth (bcrypt, ห้ามเขียน hash เอง), session ฝั่งเซิร์ฟเวอร์ (cookie), และดึงสิทธิ์ผู้ใช้ (role/branch/perms จาก `app_user`/`role`/`app_user_branch`) เข้า context ที่ server ใช้ตัดสิน — เตรียม JWT claims/หรือ server lookup ให้ RLS + เมนู + money-strip ใช้ต่อ

### Acceptance Criteria
- หน้า login ทำงาน, session ปลอดภัย (httpOnly cookie), logout ได้
- ไม่มีบัญชีที่ใช้ร่วมกันหลายคน (1 user 1 บัญชี) — ตามเกณฑ์ตรวจรับ Spec §12.1
- server รู้ perms/branch ของ user ปัจจุบันผ่าน helper เดียว (`getCurrentUser()`), unknown role → fail closed (ไม่มีสิทธิ์)
- รหัสผ่านถูก hash โดย Supabase (ยืนยันไม่มีการเก็บ plain ที่ใดเลย)

### Validation
- test: login/logout, session หมดอายุ, ผู้ใช้ inactive เข้าไม่ได้
- test: `getCurrentUser()` คืน perms ถูกตาม role seed (9 บทบาท)

### Notes
- ทดสอบล็อกอินบัญชีจริงยังทำไม่ได้จนกว่ามีรหัสผู้ใช้ (handoff §8) — เตรียม seed/test user

### Implementation Notes (ready for review)
ยึด RLS จริง (migration 06): authenticated อ่าน `app_user`/`role`/`app_user_role`/`app_user_branch` ได้ (`using true`) → getCurrentUser ใช้ publishable client + session ได้ **ไม่ต้องใช้ service_role**

Files:
- `lib/auth/permissions.ts` — `Perm`/`PermSet` (4 สิทธิ์จริง), `combinePerms` (OR หลาย role, fail closed) + test
- `lib/auth/index.ts` — `getCurrentUser()` จริง: `auth.getUser()` (ตรวจ JWT จริง) → อ่าน app_user (inactive→null) + roles + branches → perms; memoized (React cache)
- `lib/auth/actions.ts` — `login` (server action, Supabase `signInWithPassword`, hash โดย Supabase) + `logout`
- `lib/supabase/middleware.ts` + `middleware.ts` — refresh session cookie ทุก request
- `app/login/page.tsx` + `components/auth/LoginForm.tsx` (useActionState) — ล็อกอินแล้ว→redirect /dash
- `app/(app)/layout.tsx` — `getCurrentUser()` → ไม่มี session redirect `/login`; เมนู/primary/canSell จาก **role จริง**
- TopBar โชว์ชื่อผู้ใช้จริง + ปุ่มออกจากระบบ (form → logout action)

Validation: `tsc` ✅ · `eslint` ✅ · `vitest` ✅ 25/25 · `next build` ✅ (26 หน้า + middleware)
**Runtime:** `/login`=200 (มี email/password/เข้าสู่ระบบ) · `/dash` ไม่ล็อกอิน = **307 → /login** (route protection ทำงาน)

⏳ ยังทดสอบไม่ได้เอง — **login สำเร็จจริงต้องมี test user + รหัสผ่าน** (ผมจับรหัสผ่านไม่ได้ตามกฎความปลอดภัย): ผู้ใช้สร้าง user ใน Supabase (หรือใช้ seed `admin@famai.local` ถ้าทราบรหัส) แล้วลองเอง · ควรเปิด Leaked Password Protection + reset DB password ก่อน (handoff §3)
