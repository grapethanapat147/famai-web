## FAM-1004: Supabase data layer & RPC wrappers

Status: In Progress
Priority: High
Epic: FAM-E04
Refs: docs/03-data-model.md · docs/08-state-and-handoff.md · supabase/migrations/

### Summary
ชั้นเข้าถึงข้อมูล type-safe บน schema เดิม: generate types จาก DB, browser client (publishable, ผ่าน RLS) + server client (service_role, ใช้เท่าที่จำเป็น), helper query ที่เคารพ RLS, wrapper สำหรับ RPC/ฟังก์ชันที่มีแล้ว (`next_doc_no`, sell/ตัดสต๊อก, `punch_clock`, `is_all_branch`, `my_branches`, `is_admin`, `is_manager`), และ `app_setting` loader (jsonb → typed, cache)

### Acceptance Criteria
- generated DB types ใช้ทั่วแอป; ไม่มี `any` ตรง data boundary
- browser client ใช้ publishable key เท่านั้น; server client แยกไฟล์ ไม่ถูก import จาก client component (มี test/lint rule)
- `getSetting(key)` อ่านจาก `app_setting` (แปลง jsonb ถูก, `to_jsonb` semantics), มี default fallback ตาม Spec §7 — **ไม่ hardcode เกณฑ์**
- RPC wrappers typed + จัดการ error; เขียน integration test เรียกจริง (หรือ mock ตาม env กล่องทดสอบ handoff §7)

### Validation
- integration test: RLS กันข้ามสาขา (user A ไม่เห็นแถวสาขา B), settings อ่านได้
- ยืนยัน service_role ไม่อยู่ใน client bundle
- ยิง RPC จริงด้วย role จริง (handoff §9j) เท่าที่ทำได้

### Notes
- handoff §7 traps: Node parse ISO เป็น UTC, `pgcrypto` ใน `extensions`, view = เส้นแบ่งความปลอดภัย

### Implementation Notes (ready for review)
