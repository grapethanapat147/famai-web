# FAM-1018 · หน้าตั้งค่าระบบ (settings)

**Epic:** FAM-E10 (ข้อมูลและตั้งค่า)
**สถานะ:** Done (รอเจ้าของ merge + ทดสอบเขียนจริงตอนล็อกอิน admin)
**สาขา:** `feat/settings-screen`

## เป้าหมาย
UI แก้ "เกณฑ์ทั้งหมดที่ระบบใช้" (`app_setting`) โดยไม่ต้องเข้า DB console
ทุกหน้าที่ทำมาอ่านค่าจากที่นี่ (aging_days, vat_pct, finance_terms, freebie_is_cost, service_km, ฯลฯ)

## ที่มา
- `lib/settings/resolve.ts` — 15 คีย์ + ค่าเริ่มต้น (ตรง seed migration 08) · เก็บเป็น jsonb
- หลัก "ไม่มี hardcoded threshold" — ทุกเกณฑ์อยู่ใน app_setting
- **RLS: app_setting = อ่านได้ทุกคนที่ล็อกอิน แต่เขียนได้เฉพาะ `is_admin()`** → แก้ได้เฉพาะ admin (manager ดูได้อย่างเดียว)

## ขอบเขต (in)
- Route `/settings` (SSR ผ่าน RLS): โหลด `getSettings()` → ฟอร์มแบ่ง 4 กลุ่ม (สต๊อก / ขายและการเงิน / ลูกค้าและบริการ / พนักงานและเงินเดือน)
- input ตามชนิด: number, percent (%), int-list (คั่นจุลภาค), bool (toggle), time (HH:MM)
- **ตรวจสด** ด้วย `parseInput` (แหล่งตรวจเดียว client+server) — โชว์ error ต่อช่อง + ปิดปุ่มบันทึกถ้ามีค่าผิด
- `updateSettings` action: **เฉพาะ admin** (ตรงกับ RLS) + ตรวจทุกค่าใหม่ + upsert app_setting (onConflict key)
- ผู้ไม่ใช่ admin (เช่น manager) เห็นฟอร์ม read-only (input disabled, ไม่มีปุ่มบันทึก)
- helper บริสุทธิ์ + tests (8 เคส): SETTING_FIELDS ครบทุกคีย์ · formatForInput/parseInput ทุกชนิด
- `/dev/settings` preview + verify desktop/mobile ไม่มี h-scroll

## ขอบเขต (out / ตามมา)
- ประวัติการแก้ค่า (audit) · reset เป็นค่า default · ค่าตั้งค่าเฉพาะสาขา (ตอนนี้ระดับระบบ)
- ค่าตั้งค่าใหม่ที่ผูก R1 (บริษัทขายส่ง, ดอกเบี้ย tiered) เพิ่มเมื่อทำ epic นั้น
