# FAM-1145 — ปิดเงินเดือน เลข ปกส. และบัญชีธนาคาร ที่ระดับฐานข้อมูล

**สถานะ:** Done
**สาขา (git):** `feature/FAM-1145-employee-pay-rpc`
**ต้องรัน SQL:** ใช่ — `supabase/migrations/20260904140000_40_employee_pay_columns.sql`

## ปัญหา
`employee.base_salary` (เงินเดือน) กับ `ssn_no` · `bank_code` · `bank_account`
(เลขประกันสังคมและบัญชีธนาคาร — ข้อมูลอ่อนไหวตาม PDPA) อ่านได้ด้วย token ของผู้ใช้คนไหนก็ได้
ที่ยิง PostgREST ตรง ๆ **RLS กันได้แค่ระดับแถว ไม่ใช่ระดับคอลัมน์** จึงกันเรื่องนี้ไม่ได้
(FAM-1144 ปิดตาราง `payslip` ไปแล้ว แต่เงินเดือนตั้งต้นยังอยู่ที่ตาราง `employee`)

## ทำอะไรบ้าง
**ถอนสิทธิ์อ่านเฉพาะ 4 คอลัมน์** ออกจาก role `authenticated` (คือผู้ใช้ที่ล็อกอินทุกคน)
คอลัมน์อื่น (`id` `user_id` `branch_id` `emp_code` `position` `hired_at` `resigned_at`) ยังอ่านได้ตามปกติ
อีก 6 จุดในแอปที่อ่านเฉพาะคอลัมน์เหล่านั้นจึงไม่กระทบเลย

**เปิดทางเดียวให้อ่านผ่าน `employee_pay_info()`** — security definer ที่ตรวจ `has_money()`
(ทำไว้แล้วใน FAM-1144) บวกขอบเขตบริษัทให้เอง ไม่มีสิทธิ์ = ได้ลิสต์ว่าง ไม่ throw
หน้าจอจึงยังแสดง "—" ได้ตามปกติแทนที่จะพัง

**แก้ 3 จุดที่อ่านเงินเดือน** ให้ไปเรียกฟังก์ชันนี้แล้ว merge ตาม `employee_id`:
หน้าพนักงาน · หน้าเงินเดือน · ตอนสร้างสลิปปิดงวด
การเขียน (เพิ่ม/แก้พนักงาน) ไม่กระทบ — ถอนแค่สิทธิ์ `select` ไม่ได้ถอน `insert`/`update`
และจุดที่สร้างพนักงานใหม่ใช้ service role อยู่แล้ว

## ทำไมไม่ใช้ view
view ที่ `security_invoker = on` จะติดสิทธิ์คอลัมน์ของผู้เรียกเหมือนกัน ส่วน `off` จะข้าม RLS
ของตารางแม่ไปด้วย (การแยกข้อมูลตามบริษัทจะพัง) — ฟังก์ชัน security definer ที่เขียนเงื่อนไขเองจึงตรงกว่า

## เทสต์
เพิ่ม 3 เคสใน `tests/integration/security.test.ts` (รันเมื่อมี secret):
ยิงขอ `base_salary` / `ssn_no` ตรงต้องถูกปฏิเสธ**แม้เป็นแอดมิน** · คอลัมน์ทั่วไปยังอ่านได้ ·
`employee_pay_info()` คืนข้อมูลให้ผู้มีสิทธิ์ตัวเงิน และคืนลิสต์ว่างให้เซลล์

## ต้องยืนยันกับฐานข้อมูลจริง
เทสต์ในเครื่องเป็น pure logic ทั้งหมด **พิสูจน์เรื่องสิทธิ์ไม่ได้** — หลังรัน SQL ให้เปิด
หน้าพนักงานกับหน้าเงินเดือนด้วยบัญชีฝ่ายบุคคลจริง ๆ ว่าตัวเลขยังขึ้นครบ
(คำสั่งตรวจและคำสั่งย้อนกลับอยู่ในข้อความที่ส่งให้ในแชต)
