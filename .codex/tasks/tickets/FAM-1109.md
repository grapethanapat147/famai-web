# FAM-1109 · หน้าพนักงาน — ตั้งเงินเดือน/ตำแหน่ง + เพิ่มพนักงานใหม่ (รวมหน้าเดียว)

**ประเภท:** (feature) · **ที่มา:** เกรพ — ปิดช่องว่าง 2 ข้อจากผลตรวจ: (1) หน้าเงินเดือนอ่าน `base_salary` ที่ไม่มีที่ให้กรอก → ทุกคนได้ 0 (2) เพิ่มพนักงานใหม่ต้องเข้า Supabase dashboard

## ⚠️ ต้องมี env บน Vercel
`SUPABASE_SERVICE_ROLE_KEY` — จำเป็นสำหรับ **สร้างบัญชี** เท่านั้น (สร้าง auth user ได้ทางเดียว)
ถ้ายังไม่ตั้ง: หน้าอื่นทำงานปกติ · แก้ข้อมูล/เงินเดือนได้ปกติ · ปุ่มสร้างบัญชีจะขึ้น "ระบบยังไม่พร้อมสร้างบัญชี — แจ้งผู้ดูแลระบบ" (ไม่ crash)
(local ตั้งไว้แล้วใน .env.local)

## ทำ ✅ (branch feature/FAM-1109-employees) — ไม่ต้อง migration (ตาราง employee มีคอลัมน์ครบแล้ว)

### เมนูใหม่ "พนักงาน" (/employees) — admin/manager/hr · เมนู 23 → 24
- ตารางพนักงาน: ชื่อ/รหัส · ตำแหน่ง/บริษัท · วันเริ่มงาน · **เงินเดือน** (money-gated) · ปุ่มแก้ไข
- ป้ายเตือนหัวหน้า **"ยังไม่ตั้งเงินเดือน N คน"** + คนที่ยังไม่ตั้งขึ้นสีแดง "ยังไม่ตั้ง" (เห็นปัญหาทันที)
- ค้นหา (ชื่อ/รหัส/ตำแหน่ง) + กรองบริษัท + ชิปสถานะ **ทำงานอยู่ / ลาออกแล้ว / ทั้งหมด** (ดีฟอลต์ซ่อนคนลาออก)

### 1) แก้ข้อมูลพนักงาน (`updateEmployee`) — admin/manager/hr
ตำแหน่ง · รหัสพนักงาน · บริษัท · วันเริ่มงาน · **วันที่ลาออก** (กรอกแล้วหลุดจากรายชื่อทำงานอยู่) · **เงินเดือน**
- เงินเดือนเขียนได้เฉพาะผู้มีสิทธิ์ `money` (กันคนไม่มีสิทธิ์ส่งค่าทับเป็น null) · อ่านก็ตัดทิ้งฝั่ง server
- RLS employee (branch-scoped) คุมอีกชั้น · รหัสพนักงานซ้ำ → ข้อความชัด (จับ 23505)

### 2) เพิ่มพนักงานใหม่ (`createStaffAccount`) — **แอดมินเท่านั้น**
ขั้นเดียวจบ: **auth user → app_user → บทบาท → บริษัท → ระเบียนพนักงาน**
- ฟอร์ม 3 ส่วน: บัญชีเข้าสู่ระบบ (ชื่อ/ชื่อเล่น/username/อีเมล/รหัสผ่านชั่วคราว + **ปุ่มสุ่ม 12 ตัว** เลี่ยงตัวกำกวม 0/O/1/l) · สิทธิ์ (บริษัท + บทบาทหลายอย่าง) · ข้อมูลพนักงาน (กรอกภายหลังได้)
- `email_confirm: true` → พนักงานล็อกอินได้ทันที ไม่ต้องรอเมลยืนยัน
- **rollback อัตโนมัติ**: ล้มขั้นไหนก็ลบ auth user + ข้อมูลที่สร้างไปแล้วทิ้ง (กันบัญชีค้างที่ล็อกอินได้แต่ไม่มีสิทธิ์)
- หน้าจอสำเร็จโชว์อีเมล+รหัสผ่านครั้งเดียวให้แอดมินคัดลอกไปแจ้ง — รหัสผ่านไม่ถูกเก็บ/ล็อกที่ใด
- `all_branch = false` เสมอ (ให้แอดมินเปิดเองที่หน้า บัญชีผู้ใช้ ถ้าต้องการ)
- กัน username ซ้ำก่อนสร้าง · อีเมลซ้ำ/รหัสสั้น → ข้อความไทยชัดเจน
