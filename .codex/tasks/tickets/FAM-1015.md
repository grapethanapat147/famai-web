# FAM-1015 · หน้าเงินค้างรับ (ar) + ลงรับเงิน

**Epic:** FAM-E08 (ลูกค้าและการเงิน)
**สถานะ:** Done (รอเจ้าของ merge + ทดสอบเขียนจริงตอนล็อกอิน)
**สาขา:** `feat/ar-screen`

## เป้าหมาย
ติดตามยอดที่ยังไม่ได้รับ (จากไฟแนนซ์/ลูกค้า) เห็นยอดค้าง/เกินกำหนดชัด ๆ และ**ลงรับเงิน**ตัดยอดได้

## ที่มา
- data model: `receivable` (balance = generated amount_due − amount_paid) + `receipt_payment` (ledger รับเงินจริง)
- เมนู: roles admin/manager/**acct** (money=true ทั้งหมด) · R1 dashboard: ยอดค้างเป็นตัวแดงเด่น (หลักการเดียวกัน)

## ขอบเขต (in)
- Route `/ar` (SSR ผ่าน RLS): receivable + join ผู้ค้าง (บริษัทไฟแนนซ์ หรือ ลูกค้าจากการขาย) + รถ · เรียงตามกำหนด
- **ต้นทุน/เงิน guard**: `Money canSee` ตาม canSeeMoney (customer mode)
- KPI: ค้างทั้งหมด · **เกินกำหนด (แดง)** · จำนวนรายการค้าง
- FilterBar: ค้นหา + ประเภท (ไฟแนนซ์/ลูกค้า) + ยังค้าง/เกินกำหนด/ทั้งหมด
- ตาราง (มือถือ=การ์ด): ผู้ค้าง+ประเภท · ยอดตั้ง · คงค้าง (เกินกำหนด=แดง / ชำระครบ=เขียว) · กำหนด
- **ลงรับเงิน** (modal): จำนวน (default=คงค้าง) · วิธี (เงินสด/โอน/เช็ค) · เลขอ้างอิง → `recordPayment`
  - ด่านสิทธิ์ + **กันรับเกินยอด** + compare-and-swap เพิ่ม amount_paid + ปิดยอด (settled_at) + เขียน ledger `receipt_payment` (revert ถ้า ledger ล้ม)
- helper บริสุทธิ์ + tests (8 เคส): isSettled/isOverdue/clampPayment/filterReceivables/arTotals/kindLabel/canManageAr
- `/dev/ar` preview + verify desktop/mobile ไม่มี h-scroll

## ขอบเขต (out / ตามมา)
- ประวัติการรับเงินต่อรายการ (receipt_payment log) + พิมพ์ใบเสร็จ (RECEIPT ผ่าน next_doc_no)
- สร้าง receivable อัตโนมัติตอนเปิดการขาย/ไฟแนนซ์อนุมัติ (ผูกกับ FAM-1011/1028)
- รับบางส่วนหลายงวด + แจ้งเตือนก่อนถึงกำหนด
