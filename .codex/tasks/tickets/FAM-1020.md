# FAM-1020 · หน้าบัญชีผู้ใช้ (users) — จัดการบทบาท/สาขา (RBAC)

**Epic:** FAM-E12 (ความปลอดภัย / สิทธิ์)
**สถานะ:** Done (รอเจ้าของ merge + ทดสอบเขียนจริงตอนล็อกอิน admin)
**สาขา:** `feat/users-screen`

## เป้าหมาย
จัดการผู้ใช้ + บทบาท (role) + สาขาที่เข้าถึง + เปิด/ปิดใช้งาน — รากของ RLS/permission ที่ทุกหน้าพึ่งพา

## ที่มา
- data model: `app_user` (all_branch/is_active) · `role` (perms jsonb) · `app_user_role` · `app_user_branch`
- **RLS: อ่านได้ทุกคน (ต้องใช้แสดงชื่อ) · แก้ได้เฉพาะ `is_admin()`** → admin เท่านั้น
- `app_user.id` อ้าง `auth.users(id)` → **สร้างผู้ใช้ใหม่ต้อง provision auth** (เลื่อนเป็น follow-up)

## ขอบเขต (in)
- Route `/users` (SSR ผ่าน RLS): รายชื่อ + บทบาท + สาขา + สถานะ · **หน้ากันด้วย canManageUsers=admin** (ตรงกับ RLS)
- FilterBar: ค้นหา (ชื่อ/username) + บทบาท + ใช้งาน/ปิดใช้งาน
- ตาราง (มือถือ=การ์ด): ชื่อ (+nickname, ป้าย "คุณ") · บทบาท (ป้าย) · สาขา (ทุกสาขา/รายชื่อ) · สถานะ
- **แก้สิทธิ์ (Drawer)**: toggle เปิดใช้งาน · toggle เห็นทุกสาขา · multi-select บทบาท · multi-select สาขา (ข้ามถ้าเห็นทุกสาขา) → `updateUserAccess`
- action: **เฉพาะ admin** + **กันแอดมินล็อกตัวเอง** (ถอด admin/ปิดตัวเองไม่ได้) + sync role/สาขา **เพิ่มก่อนลบทีหลัง** (กันช่วงว่างสิทธิ์) + ตรวจ id ที่ส่งมามีจริง
- helper บริสุทธิ์ + tests (6 เคส): filterUsers/diffIds/selfLockout/canManageUsers
- `/dev/users` preview + verify desktop/mobile ไม่มี h-scroll

## ขอบเขต (out / ตามมา)
- **สร้าง/เชิญผู้ใช้ใหม่** (ต้อง Supabase auth admin API — provision auth.users) · รีเซ็ตรหัสผ่าน
- แก้ perms รายสิทธิ์ของ role (ตอนนี้ role.perms คงที่ตาม seed) · audit ว่าใครแก้สิทธิ์ใคร
