# FAM-1028 · งานสินเชื่อเต็ม + เปิดดีล/ลูกค้าเท (deal follow-ups)

**Epic:** FAM-E08 (ลูกค้าและการเงิน)
**สถานะ:** Done — finance workflow + ลูกค้าเท void (PR feat/deal-create). เปิดดีลใหม่ = บล็อกรอ sell_unit RPC (migration 17)
**ขึ้นกับ:** FAM-1013 (หน้าดีลตอนนี้ list + เลื่อนขั้นทะเบียน · สินเชื่อยัง read-only)

## เป้าหมาย
เติมส่วนที่ FAM-1013 กันไว้ให้ครบวงจรดีล

## ขอบเขต
- **งานสินเชื่อ (finance_case)** ✅: เลื่อนสถานะ (ส่งเรื่อง→ยื่นเอกสาร→รอผล→อนุมัติแล้ว|ปฏิเสธ) + `finance_case_event` log · ปฏิเสธ→ยื่นใหม่/ยกเลิก
- **ลูกค้าเท** ✅ (R1): void ดีล + เหตุผลจำเป็น (PR feat/deal-create)
- **เปิดดีลใหม่** ⛔ บล็อก: สร้าง sale+registration = atomic หลายตาราง ต้องผ่าน `sell_unit` RPC (migration 17 DRAFT ยังไม่ apply) — ทับกับหน้า `/sell` (form-only รอ RPC เดียวกัน) ไม่ควรทำ CAS ขนานแยก
- ยังตามมา: การเงินกดอนุมัติ (R1 A4 `sale.payment_confirmed_by`) · ดอกเบี้ย tiered (R1 B2) · ส่งต่อฝ่ายบริการ · แจ้งเตือน email/เว็บ (R1 B3)

## หมายเหตุ — ลูกค้าเท void (Done)
- `canVoidDeal` (admin/manager เท่านั้น — เข้มกว่าเลื่อนขั้น) + `isVoidableStage` (ห้ามหลังส่งมอบ) ใน lib/deal/deals.ts + tests
- action `voidDeal`: ด่านสิทธิ์ + เหตุผลจำเป็น + อ่านขั้นทะเบียนจริงกันยกเลิกหลังส่งมอบ + **CAS** soft-void (`voided_at`/`voided_reason`, guard `is voided_at null`) · best-effort คืนรถ sold→available (CAS) + ปิด finance_case (→ยกเลิก, idempotent)
- UI: DealDrawer มีลิงก์ "ลูกค้าเท — ยกเลิกดีล" (สองสเต็ป: กด→ช่องเหตุผล+ยืนยัน/ไม่ยกเลิก) โผล่เฉพาะ canVoid && ยังไม่ส่งมอบ
- verify /dev/deal: void โผล่เฉพาะดีลก่อนส่งมอบ, ยืนยันปิดเมื่อเหตุผลว่าง, ส่งเหตุผล→สำเร็จปิดดรอเวอร์, ดีลส่งมอบแล้วไม่มีลิงก์, mobile 375 ไม่มี h-scroll, console สะอาด · tsc+eslint+build ผ่าน · vitest 190 ผ่าน · เขียนจริงยังไม่ทดสอบ (ล็อกอินยังไม่ได้)
