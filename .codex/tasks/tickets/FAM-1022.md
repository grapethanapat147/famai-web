## FAM-1022: Company entity + branch hierarchy (R1)

Status: Done
Priority: High
Epic: FAM-E05
Refs: .codex/specs/revision-1-client-feedback.md §B1 · docs/08-state-and-handoff.md §4 · migration `..._16_company.sql`

### Summary
R1 ต้องการเปลี่ยน "สาขา" → "บริษัท" + เพิ่มสาขาย่อยใต้บริษัท และโอนข้ามบริษัทต้องเปิดบิลขายก่อน
เพิ่ม entity `company` เป็นแม่ของ `branch` แบบ**รองรับทั้ง 1 บริษัท และหลายบริษัท** — ปลดล็อกหน้ารับรถ/ขาย

### Decision / assumption (รอเจ้าของยืนยัน)
- ยังไม่ทราบจำนวนบริษัทจริง → migration seed **1 บริษัท (FAMAI) ครอบ 3 สาขาเดิม** เป็น default (แก้เป็นหลายบริษัทได้)
- **เลขเอกสารยังแยกตามสาขา** (`next_doc_no` เดิม ไม่พัง) · ใบกำกับภาษีใช้ `company.tax_id` (fallback `branch.tax_id`)
- **RLS ไม่เพิ่มการกันระดับบริษัท** — branch isolation เดิมพอ (user มีเฉพาะสาขาของบริษัทตัวเองอยู่แล้ว)

### Scope
- [x] migration `..._16_company.sql` — `company` table + `branch.company_id` + seed + RLS (draft, รอ apply)
- [ ] types: เพิ่ม `company` + `branch.company_id` ใน `lib/supabase/database.types.ts`
- [ ] helper อ่าน company + สาขาในบริษัท (สำหรับ dropdown บริษัท→สาขา)
- [ ] ใช้ในหน้า **รับรถ (FAM-1007)** และ **ขาย (FAM-1011)**: เลือกบริษัท→สาขา + เตือน "เลือกไม่ตรงกับสาขาที่รถอยู่ ให้ย้ายรถก่อน"
- [ ] โอนย้าย: ข้ามบริษัท=ธุรกรรมขาย · ในบริษัท=ย้ายสาขา (สาขากรอก manual ได้) — ต่อใน transfer/B2B ticket

### Acceptance Criteria
- schema: ทุก branch มี `company_id` · สร้าง/แก้บริษัทได้ (admin) · เลือกบริษัท→สาขาในฟอร์มรับรถ/ขาย
- โอนข้ามบริษัททำตรง ๆ ไม่ได้ ต้องเปิดบิลขาย · ในบริษัทเดียวกันย้ายสาขาได้
- เอกสาร/ใบกำกับภาษี header ใช้ข้อมูลบริษัทถูกต้อง · เลขเอกสารไม่ซ้ำ (แยกสาขา)

### Validation
- apply migration (เจ้าของ) → ยิงตรวจ: branch ทุกแถวมี company_id · anon อ่าน company ไม่ได้/authenticated อ่านได้
- typecheck/build หลังอัปเดต types

### ⚠️ Blocked-until
- เจ้าของยืนยัน **จำนวนบริษัทจริง + mapping สาขา + เลขผู้เสียภาษี** ก่อน seed/apply จริง และก่อนออกใบกำกับภาษี
