## เป้าหมาย
Cron job ที่ 4 (customer retention): **สร้าง** `follow_up_task` ต่อการขาย × รอบติดตาม (7/30/90/365/1095 วัน) เมื่อถึงกำหนด → โผล่ในหน้า "ติดตาม" · cron ที่ **สร้าง record** ตัวแรก (idempotent)

## ทำอะไร
- **`lib/automation/clock.ts`** — เพิ่ม `addDays(iso, n)` (ข้ามเดือน/ปี) + tests
- **`lib/automation/followup.ts`** (pure) — `plannedFollowUps(sales, existingKeys, cadenceDays, today)`: ต่อการขาย × cadence ที่ถึงกำหนด (soldAt+d ≤ today) และยังไม่มี (sale,kind) · `cadenceKind` map 365→1y, 1095→3y (ตรงสคีมา) + tests
- **`app/api/cron/sale-followup/route.ts`** — auth → อ่าน sale (ตัด voided) + follow_up_task เดิม + setting `follow_up_cadence` → คำนวณที่ต้องสร้าง → **insert** + LINE สรุป · `?preview=1` ดูรายการไม่เขียน
  - **idempotent**: กันซ้ำด้วย existing (sale,kind) → รันซ้ำไม่เพิ่มงานเดิม
- **`lib/supabase/database.types.ts`** — เพิ่ม type `FollowUpTask` + `follow_up_task: Table<>` (เดิมตกหล่นจาก types ที่ hand-maintain → `.from()` เป็น never)
- **vercel.json**: cron `0 5 * * *` (12:00 ไทย)
