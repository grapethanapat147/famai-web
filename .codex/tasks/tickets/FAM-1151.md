## สิ่งที่ตรวจ
ไล่ทุก query ของทุกหน้าใน `app/(app)` ว่าเรียงยังไง (ทั้งฝั่ง SQL และฝั่ง client หลังประกอบแถว)
ผลคือ **ส่วนใหญ่เรียงถูกอยู่แล้ว** มีหน้าเดียวที่ต้องแก้จริง

| หน้า | เดิม | ผล |
|---|---|---|
| **สต๊อกรถ** | `received_at` เก่า→ใหม่ | **แก้เป็นใหม่→เก่า** |
| ลูกค้าและดีล · ใบเสนอราคา · ค่าใช้จ่าย · ขายส่ง · โอนย้าย · ประวัติการแก้ไข · ศูนย์ซ่อม · บัญชี | ใหม่→เก่าอยู่แล้ว | ไม่แตะ |
| งานทะเบียน | เรียงตามวันค้าง (ค้างนานสุดขึ้นบน) ฝั่ง client | **ไม่แตะ — เป็นคิวงาน** |
| เงินค้างรับ | เรียงตามวันครบกำหนด | **ไม่แตะ — เป็นคิวงาน** |
| พนักงาน · ภาพรวมการเข้างาน | เรียงตามชื่อ | ไม่แตะ (ทำเนียบรายชื่อ) |
| เงินเดือน | เรียงตามยอดสุทธิ | ไม่แตะ |
| รุ่นรถ · อะไหล่ · ผู้ใช้ · สาขา | เรียงตามชื่อ/รหัส + มีตัวเลือกเรียงเอง | ไม่แตะ (แคตตาล็อก) |

## ที่แก้
`สต๊อกรถ` เปลี่ยนเป็นใหม่ล่าสุดขึ้นบน — เป็นลิสต์ไว้ "ดูของที่มี" ไม่ใช่คิวงาน
ส่วนรถที่ค้างนานมีการ์ดเฉพาะของมันอยู่แล้วที่หน้าแรก จึงไม่เสียการมองเห็นรถค้างไป

## สองหน้าที่ตั้งใจไม่แก้
**งานทะเบียน** กับ **เงินค้างรับ** เป็น **คิวงาน** ไม่ใช่ลิสต์ระเบียน — ของที่ค้างนานที่สุด
ต้องอยู่บนสุดเพราะนั่นคือสิ่งที่ต้องรีบทำ (คำอธิบายเมนูของงานทะเบียนก็เขียนไว้ว่า "เรียงตามค้างนาน")
ถ้าเกรพอยากให้สองหน้านี้เรียงใหม่ก่อนด้วย บอกได้ แก้บรรทัดเดียวต่อหน้า
