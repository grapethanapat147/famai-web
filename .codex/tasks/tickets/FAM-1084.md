# FAM-1084 · แคชข้อมูลอ้างอิง (settings/theme/สาขา/บริษัท) ลด round-trip ต่อการนำทาง

**Epic:** (perf) · **สถานะ:** In Progress (branch perf/FAM-1084-reference-cache)
**ที่มา:** เกรพ — ต่อจาก FAM-1082 (parallelize getCurrentUser) อยากให้สลับหน้าไว/เว็บลื่นขึ้นอีก

## แนวคิด
ข้อมูลอ้างอิงที่ "เหมือนกันสำหรับทุกผู้ใช้" และเปลี่ยนแทบไม่บ่อย — `app_setting` (ตั้งค่า+ธีม), `branch`, `company` — ทุกตารางเป็น RLS `for select to authenticated using (true)` (แถวเดียวกันทุก user) จึงแคชระดับ global ข้ามรีเควสต์ได้ปลอดภัย

ตอนนี้ query ซ้ำทุกหน้า:
- **ธีม** (`getThemeConfig` → `app_setting`) ยิงใน `ThemeStyle` ที่ root layout → **ทุกครั้งที่เปลี่ยนหน้า**
- **settings** (`getSettings`) ใน dash/sell/settings
- **สาขา/บริษัท** ยิงซ้ำใน ~11 หน้า (dash, stock, sell, report, transfer, users, imp, quote, deal, service, payroll)

## ทำ
- `lib/reference/cache.ts` — getter แคชด้วย `unstable_cache` + tag + `revalidate:300`
  - ใช้ service_role client (รันนอก request scope อ่าน cookie ไม่ได้; ตารางไม่มีข้อมูลเงิน/ความลับ)
  - **resilient**: แคชพลาด/ไม่มีคีย์ → fallback อ่านสดผ่าน session client (พฤติกรรมเดิม) → ไม่ regress
  - getter: `getSettingsCached`, `getThemeConfigCached`, `getBranchesCached`/`getActiveBranches`, `getCompaniesCached`
  - `revalidateReference(...tags)` → `revalidateTag`
- แก้ที่ต้นทาง (ได้ผลทุก consumer ไม่ต้องแก้รายหน้า): `getSettings()` + `getThemeConfig()` → เรียกเวอร์ชันแคช
- migrate สาขา/บริษัทใน 11 หน้า → getter แคช
- revalidate หลังบันทึก: `updateSettings`/`updateThemeSettings` → `ref:settings`; `updateOrgInfo` → `ref:branches`+`ref:companies`
