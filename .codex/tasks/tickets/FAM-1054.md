# FAM-1054 · ฝังรูปรถจริงในการ์ด OG (แก้ WebP crash)

**Epic:** FAM-E11 (Public Catalog) · **สถานะ:** In Progress (branch feat/og-real-photo)
**ที่มา:** เกรพ — "ฝังรูปรถจริงในการ์ด OG ต่อ" (ตามมาจาก FAM-1053 "ตามมา")

## บั๊กที่เจอ (สำคัญ)
FAM-1053 ฝังรูปด้วย `<img src={webpBucketUrl}>` ใน ImageResponse — **แต่รูปรถเก็บเป็น WebP** (จากหน้าแอดมิน FAM-1024) และ **satori/next-og เรนเดอร์ WebP ไม่ได้** → OG endpoint **crash 500** ทุกรุ่นที่มีรูป (บั๊กแฝง เพราะยังไม่มีรูปในระบบ)
- พิสูจน์: WebP data-URI → 500 `TypeError: u2 is not iterable` · PNG data-URI เดียวกัน → 200 ✓

## แก้ยังไง
- OG generator: ดึงรูป full → **แปลง WebP→PNG ด้วย `sharp`** (เป็น dep ของ next อยู่แล้ว ไม่เพิ่มใหม่) → ฝังเป็น PNG data-URI · พลาด → ตกไปการ์ดไม่มีรูป (ไม่ crash)
- `export const runtime = "nodejs"` (sharp ต้อง Node) · ใช้รูป full (คมกว่า) resize 940×1260 cover
- helper `modelPhotoUrl` + `galleryImages` (มีมาแต่ FAM-1051) ใช้เลือกรูป full

## Verify (end-to-end, มี cleanup)
- WebP-in-satori ล้มจริง (throwaway route) · PNG เรนเดอร์ได้ → ยืนยันสาเหตุ
- แทรกรูป WebP ทดสอบให้ B6FU00 ชั่วคราว (service_role) → OG endpoint **200, 96KB, เห็นรูปครึ่งขวา** (เดิม no-photo 49KB) · แล้ว **ลบรูป+ไฟล์คืน** (0 rows, pub.model photos=0)
- OG กลับเป็นการ์ดไม่มีรูป 200 ปกติ · tsc + eslint + vitest (250) + build ผ่าน
