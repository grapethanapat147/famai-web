# FAM-1031 · หน้าภาพรวมการเข้างาน (attend)

**Epic:** FAM-E09 (บัญชีและพนักงาน)
**สถานะ:** Done (read-only — verify ได้เต็ม)
**สาขา:** `feat/attend-screen`

## เป้าหมาย
ภาพรวม "ใครมาแล้ว ใครสาย ใครยังไม่มา" ต่อวัน — เปิดฝั่งอ่านของกลุ่ม HR/attendance

## ที่มา
- data model: `attendance` (status ปกติ|สาย|ลา|ขาด, check_in/out, late/ot minutes) + `leave_request` + `employee`
- roles: admin/manager/hr · **read-only** (ไม่มี write) → verify เต็ม
- RLS: attendance/leave_request/employee scoped ตามสาขา (migration 06)

## ขอบเขต (in)
- Route `/attend?date=YYYY-MM-DD` (SSR ผ่าน RLS): พนักงาน active + attendance วันนั้น + ใบลาที่อนุมัติครอบวันนั้น
- **สถานะคำนวณจากระเบียนจริง**: มีแถว attendance → ใช้ค่านั้น · ไม่มี → ลา>เช็กอิน>วันนี้(ยังไม่มา)>อดีต(ขาด)
- หน้ากันด้วย `canViewAttend`=admin/manager/hr
- date picker (เปลี่ยนวัน → re-fetch ผ่าน `?date=`) + สรุปตามสถานะ (กดกรอง) + ค้นหา
- ตาราง (มือถือ=การ์ด): พนักงาน+ตำแหน่ง · สถานะ (5 แบบ) · เวลาเข้างาน (แปลงเป็นเวลาไทย + สายกี่นาที) · OT
- helper บริสุทธิ์ + tests (6 เคส): resolveStatus/leaveCovers/filterRows/statusCounts/canViewAttend
- database.types: เพิ่ม employee/attendance/leave_request
- `/dev/attend` preview + verify desktop/mobile ไม่มี h-scroll

## ขอบเขต (out / ตามมา → FAM-E09 hr/payroll)
- **ลงเวลา (clock in/out)** พร้อมหลักฐาน geo/photo (R1: หมายเหตุ+เหตุผล+แนบใบรับรองแพทย์) = หน้า hr
- **อนุมัติใบลา** (ลิงก์ไปคนอนุมัติ, โควตาลาครบ→กดไม่อนุมัติ+เหตุผล — R1) = หน้า hr
- ปฏิทินคนลารายเดือน (R1) = หน้า cal · แก้/ทบทวน attendance (attendance_review migration 11)
