## 1) ข้อมูลตัวอย่าง — `supabase/seed/demo.sql` + `demo-cleanup.sql`
พบร่างที่ยังไม่ได้ commit ในเครื่อง (จาก session ก่อนหน้า) → ตรวจทั้งไฟล์แล้วรับมาต่อ
เรื่องราวเดียวกันทั้งระบบ: ลูกค้าคนเดิมโผล่ตั้งแต่ลีด → ขาย → ไฟแนนซ์ → ทะเบียน → เอกสาร → รอรับเงิน → ศูนย์ซ่อม → เตือนเช็กระยะ
พนักงานคนเดิมโผล่ใน ลงเวลา → OT → เงินเดือน (งวด ส.ค. ปิดแล้ว) → ใบนำส่ง ปกส. · บิลขายส่ง · โอนย้าย · ใบเสนอราคา · ค่าใช้จ่าย · ปฏิทิน
บัญชีทดลอง 7 คนครบทุกบทบาท (`*.demo@famai.local` / `Famai@2569`)

**ตรวจแล้ว (แบบ static — เครื่องนี้ไม่มี Docker จึงรันกับฐานข้อมูลจริงไม่ได้):**
- ทุกคอลัมน์ที่ insert มีจริงใน migrations (สคริปต์ตรวจอัตโนมัติ 40 ตาราง) · ใช้คอลัมน์จาก migration 24/25/28/31–35 ครบ
- ตัวเลขทวนมือแล้วตรงทั้งหมด: ยอดจัด = ยอดเต็ม − ดาวน์ · VAT 7% รวมใน · สลิปตรงสูตร `computePayslip` (OT/คอม/ปกส.) · OT ในสลิป ส.ค. = ผลรวมบันทึกเวลา · สต๊อกอะไหล่ = ผลรวมการเคลื่อนไหว · บิลขายส่งรวมถูก
- ตั้งใจใส่ "จุดที่ระบบต้องเตือน" ไว้ให้เห็น: ทิสโก้ไม่มีเลขผู้เสียภาษี · กานดาไม่มีเลข ปกส. · วิชัยไม่มีบัญชีธนาคาร · หัวเทียน/ผ้าคลุมต่ำกว่าขั้นต่ำ · น้ำมันเครื่องหมด · FCG01 ยังไม่ปักหมุด · เคสไฟแนนซ์ปฏิเสธ · ใบเสร็จที่ยกเลิก · รถค้างเกิน 90 วัน

**แก้จากร่างเดิม:**
- ห่อทั้งไฟล์ใน `begin … commit` — ล้มตรงไหนย้อนกลับหมด ไม่เหลือข้อมูลครึ่ง ๆ
- id `…e2` ถูกใช้ซ้ำ 2 ตาราง (ค่าใช้จ่าย + โปรโมชัน) → แยก
- แถวลา/ขาดถูกประกาศซ้ำสองที่ในลิสต์ลงเวลา → เหลือที่เดียว
- **cleanup กันติด FK:** ถ้าเคยล็อกอินด้วยบัญชีทดลองไปแก้ข้อมูลจริง หรือพนักงานจริงลงเวลาที่จุดตัวอย่าง แถวจริงจะชี้มาที่ id ตัวอย่าง → เดิมลบไม่ผ่าน · เพิ่มบล็อก "ปลดการอ้างอิง" (ตั้ง null 20 คอลัมน์) ก่อนลบ ไม่แตะข้อมูลจริง
