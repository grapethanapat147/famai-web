## สิ่งที่พบก่อนลงมือ (สำคัญกว่าตัวงาน)
ตอนปิด FAM-1145 ผมบอกไว้ว่า *"กลุ่มที่เหลือทำเหมือนกันทุกประการ ต่างแค่จำนวนจุด"* — **ไม่จริง**

ทั้งแอปใช้แพตเทิร์นเดียวกันหมดคือ **ดึงคอลัมน์เงินมาทั้งก้อน แล้วค่อยตัดทิ้งฝั่งเซิร์ฟเวอร์**
(`stripMoneyFields` — ตรวจแล้วทุกหน้าที่ดึงคอลัมน์เงิน**มีด่านนี้ครบ** ชั้นแอปไม่มีรูรั่ว)
แต่แปลว่าหน้าที่ **เซลล์ / สต๊อก / ช่าง** เปิด ก็มี `cost` อยู่ใน query ด้วย
ถอนสิทธิ์อ่านคอลัมน์ตรง ๆ = query พังทั้งหน้า ไม่ใช่แค่ตัวเลขหาย

หน้าที่ติดกับดักนี้: สต๊อกรถ · ขายรถ · ลูกค้าและดีล · รายงาน · หน้าแรก · อะไหล่ · ศูนย์ซ่อม · ขายส่ง
และมีจุดที่หนักกว่านั้นคือ `parts/actions.ts` กับ `service/actions.ts` ที่ **อ่าน `part.cost` ขณะทำงานในสิทธิ์ของสต๊อก/ช่าง**
เพื่อแช่ต้นทุนลง `part_movement.unit_cost` (FAM-1137) — ถอนสิทธิ์แล้วการเบิกอะไหล่จะพัง

→ กลุ่มที่เหลือต้อง **รื้อวิธีดึงข้อมูลของแต่ละหน้า** ไม่ใช่แค่ revoke + RPC · แยกเป็นตั๋วต่อไป

## ทำอะไรบ้าง (เฉพาะที่ปิดได้โดยไม่ต้องรื้อหน้าจอ)
**`price_history.cost` + `vat`** — RLS ของตารางอ้างอิงคือ `for select using (true)`
**ทุกคนที่ล็อกอินอ่านราคาทุนของทุกรุ่นได้ตรง ๆ ผ่าน PostgREST** (รูที่ใหญ่ที่สุดในชุดนี้)
ในแอปมีหน้าเดียวที่อ่าน `cost` คือหน้ารุ่นรถ ซึ่งเปิดให้แค่ admin/manager — ทั้งคู่มีสิทธิ์เงิน
ปิด `vat` คู่กันด้วยเพราะถอดกลับเป็นทุนได้ (ทุน = vat ÷ 0.07) และในแอปเขียนอย่างเดียว

**`motorcycle_unit.cost_vat`** — ในแอป **เขียนอย่างเดียว ไม่มีหน้าไหน select เลย**
ถอนสิทธิ์ได้โดยไม่ต้องแก้โค้ดสักบรรทัด

**`price_history_cost()`** — ทางเดียวที่จะอ่านราคาทุนของรุ่น เปิดให้เฉพาะ `has_money()`
หน้ารุ่นรถเรียกฟังก์ชันนี้แล้ว merge ด้วยคีย์ `variant_id|effective_from`

## สองชั้นนี้ห้ามถอดอันใดอันหนึ่ง
ฐานข้อมูลรู้แค่ **สิทธิ์ตามบทบาท** — ไม่รู้จัก **โหมดลูกค้า** ซึ่งเป็น cookie ฝั่งแอป
ผู้บริหารที่เปิดโหมดลูกค้าอยู่ยังมี `has_money() = true` ในสายตา DB
หน้าจอจึงต้องเรียก `stripMoneyFields` ต่อไปเหมือนเดิม เขียนกำกับไว้ทั้งใน migration และในโค้ดแล้ว
