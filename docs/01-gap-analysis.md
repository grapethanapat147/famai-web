## สรุปผู้บริหาร

Prototype v0.5 **ดีกว่าที่ร่างหน้าจอใน deck แสดงไว้มาก** — มี 14 หน้าจอ, dashboard คำนวณจากข้อมูลจริง,
ตรวจเลขเครื่อง/เลขถังซ้ำได้จริง, มีระบบตั้งค่าเกณฑ์ครบ และตัวมันเองก็ซื่อสัตย์พอที่จะติดป้ายบอกว่าข้อมูลไหนจริงข้อมูลไหนสมมุติ

แต่เมื่อกางผังไวท์บอร์ดมาเทียบทีละข้อ พบว่า

| | จำนวน |
|---|---|
| ✅ ทำได้ครบตามที่ขอ | 12 หัวข้อ |
| ⚠️ มีแต่ไม่ครบ / เป็นของปลอม | 11 หัวข้อ |
| ❌ ไม่มีเลย | 13 หัวข้อ |

**สามเรื่องที่ต้องแก้ก่อนเอาไปใช้จริง**

1. **เลขใบกำกับภาษีซ้ำได้** — ผิดกฎสรรพากร (§2.2)
2. **ระบบสิทธิ์ไม่ทำงาน** — สิทธิ์ 5 ตัว ใช้จริงตัวเดียว และเมนูไม่ถูกกรองตามบทบาทเลย (§3.2)
3. **ไม่มีฐานข้อมูล** — ปิดหน้าเว็บแล้วข้อมูลหาย (§3.1)

**เรื่องที่ขาดแล้วเจ็บที่สุดในเชิงธุรกิจ** คือ **โมดูล Service** — ไวท์บอร์ดเขียนไว้ละเอียดที่สุดช่องหนึ่ง
แต่ในโปรโตไทป์ไม่มีแม้แต่หน้าจอเดียว ทั้งที่เป็นแหล่งรายได้ซ้ำและเป็นตัวรักษาลูกค้าเก่า

## 2. ของที่มีอยู่แต่ยังใช้จริงไม่ได้

### 2.1 🔴 พิมพ์ไม่ได้เลยทั้งระบบ

ปุ่ม `พิมพ์` ทุกปุ่มเรียก `toast('สั่งพิมพ์แล้ว')` แล้วจบ
**ไม่มี `window.print()` ไม่มี PDF ไม่มี export CSV/Excel ที่ไหนเลยทั้งไฟล์**

ร้านมอเตอร์ไซค์ต้องพิมพ์ทุกวัน — ใบเสร็จ ใบกำกับภาษี ใบเสนอราคา สลิปเงินเดือน

### 2.2 🔴 เลขที่เอกสารซ้ำได้ — ผิดกฎสรรพากร

```js
เลขใบเสร็จ      = 'RC-' + (จำนวนใบขาย + 1)
เลขใบกำกับภาษี  = 'TX-' + (จำนวนใบขาย + 1)
```

ปัญหา 3 ชั้นซ้อนกัน:
1. **ใช้ตัวนับเดียวกัน** ใบเสร็จเลข 5 กับใบกำกับภาษีเลข 5 คือรายการเดียวกัน
2. **รีเซ็ตทุกครั้งที่เปิดหน้าใหม่** เพราะนับจากจำนวนแถวในหน่วยความจำ
3. **ไม่แยกสาขา** 3 สาขาออกเอกสารพร้อมกัน = เลขชนแน่นอน

ใบกำกับภาษีต้องมีเลขเรียงต่อเนื่องและห้ามซ้ำ — ข้อนี้ต้องแก้ก่อนใช้จริงเด็ดขาด

### 2.3 🔴 ข้อมูลบริษัทฝังตายในโค้ด

ชื่อบริษัท ที่อยู่ และเลขประจำตัวผู้เสียภาษี (`0 0000 00000 00 0`) เขียนติดอยู่ในโค้ด
**และไม่มีในหน้าตั้งค่า** — วันที่บนเอกสารก็ฝังเป็น 29 ก.ค. 2026 ตายตัว ไม่ได้ใช้วันที่ขายจริง

### 2.4 ค่าที่ตั้งไว้แต่ไม่มีใครใช้

| ตั้งค่าได้ | ใช้จริง |
|---|---|
| `CFG.km` — เตือนเช็กระยะ 500/1,000/4,000/8,000 | ❌ ไม่มีโค้ดเรียกใช้ |
| สิทธิ์ `allBranch` · `editBack` · `approve` · `admin` | ❌ แสดงผลได้ กดได้ แต่ไม่มีโค้ดอ่านค่า |
| ช่อง "หมายเหตุ" ในหน้าขาย | ❌ ไม่มีโค้ดอ่านค่า |
| สถานะ `จองแล้ว` / `กำลังโอนย้าย` | ❌ ไม่มีโค้ดตั้งค่า |
| 9 จาก 20 ช่องในข้อมูลรถตั้งต้น | ❌ ไม่ถูกอ่าน |

## 3. ปัญหาโครงสร้าง

### 3.1 🔴 ไม่มีฐานข้อมูล ไม่มี login จริง

- ข้อมูลอยู่ในหน่วยความจำของหน้าเว็บ **ปิดแล้วหาย** (โปรโตไทป์เขียนบอกเองที่ท้าย sidebar)
- ไม่มี `localStorage`, ไม่มี `fetch`, ไม่มี API — ไม่มีการเก็บข้อมูลใด ๆ ทั้งสิ้น
- **ไม่มีหน้า login** — ตัวเลือกบทบาทบน topbar เป็นแค่ "ดูในมุมมองของ..."
- ปุ่มเปลี่ยนรหัสผ่านแค่ขึ้นข้อความ ไม่ได้ทำอะไร

→ ตรงข้ามกับโจทย์ "ใช้ผ่านอินเทอร์เน็ต เชื่อมหลายสาขา" โดยสิ้นเชิง

### 3.2 🔴 ระบบสิทธิ์ไม่ได้กันอะไรจริง

มีบทบาท 9 แบบ สิทธิ์ 5 ตัว — **แต่มีแค่ `money` (เห็นต้นทุนและกำไร) ที่มีโค้ดอ่านค่า**

และที่สำคัญกว่า: **เมนูไม่ถูกกรองตามบทบาทเลย** ทุกคนเห็นครบ 14 เมนู
รวมถึงหน้าจัดการผู้ใช้และหน้าตั้งค่าระบบ

ทั้งที่ deck มี permission matrix ชัดเจนแล้วว่าใครควรเห็น dashboard ตัวไหน

### 3.3 🔴 สาขาไม่ใช่ของจริงในระบบ

- สาขาเป็นเพียง**ข้อความ**ที่ derive จากข้อมูลรถ ไม่มีตารางสาขา ไม่มีที่อยู่ ไม่มีเลขผู้เสียภาษีรายสาขา
- **ใบขายไม่มีช่องสาขาของตัวเอง** ต้องย้อนไปดูจากคันรถ
- สิทธิ์ `allBranch` ไม่จำกัดอะไรจริง — ผู้ใช้สาขาเดียวเห็นข้อมูลทุกสาขาอยู่ดี
- ไม่มีการโอนย้ายรถระหว่างสาขา
- เลขเล่มใบกำกับภาษีเดาจากอักษรย่อชื่อสาขาของ*คันรถ* ไม่ใช่ของสาขาที่ออกเอกสาร

> ข้อมูลจริงยิ่งย้ำปัญหานี้ — ไฟล์ยามาฮ่า **ไม่ได้บอกชื่อสาขา** (เป็น `สำนักงานใหญ่` ทั้ง 50 แถว)
> และ prefix เลขเอกสารก็ไม่ตรงกับรหัสสาขา ดูรายละเอียดที่ `00-yamaha-export-analysis.md` §3.1

### 3.4 🟠 ความสัมพันธ์ผูกด้วยชื่อคน ไม่ใช่ id

`ใบขาย.ลูกค้า`, `งานติดตาม.ลูกค้า`, `เคสสินเชื่อ.ลูกค้า`, `ใบลา.พนักงาน`, `ลงเวลา.พนักงาน` — **ทั้งหมดเก็บเป็นชื่อ**

→ แก้ชื่อลูกค้าหรือพนักงานหนึ่งครั้ง ข้อมูลจะขาดจากกันเงียบ ๆ ไม่มีอะไรเตือน
→ ลูกค้าชื่อซ้ำกันสองคนจะกลายเป็นคนเดียวกัน

### 3.5 🟠 ปัญหาย่อยที่ต้องแก้ไปพร้อมกัน

| ปัญหา | ผลที่ตามมา |
|---|---|
| id ของ**คันรถ**กับ**ผู้ใช้**ใช้ตัวสร้างเดียวกัน (`U1`, `U2`, …) | ไม่ชนเพราะบังเอิญใช้ตัวนับร่วมกัน — เปราะมาก |
| ข้อมูลลงเวลาผูกกับพนักงานด้วย**ลำดับที่** | สลับลำดับพนักงานเมื่อไหร่ เวลาเข้างานสลับคนทันที |
| `refreshAll()` วาดใหม่ทุกหน้าทุกครั้งที่แก้ข้อมูล | ที่ 50 คันไม่รู้สึก ที่ 5,000 คันจะช้ามาก |
| ไม่มี audit log | ไม่รู้ว่าใครแก้อะไรเมื่อไหร่ — สำคัญมากเมื่อมี 3 สาขาหลายคน |
| ไม่มีลบ / ไม่มีย้อนกลับ / ไม่มีกล่องยืนยัน | กดผิดแล้วแก้ไม่ได้ |
| ไม่ responsive จริง (sidebar 230px ไม่ยุบ) | ใช้บนมือถือหน้างานไม่ได้ ทั้งที่ LYY มีเมนูมือถือ |
| เวลาในระบบหยุดนิ่งที่ 29 ก.ค. 2026 | ต้องเปลี่ยนเป็นเวลาจริง |

## 4. เรื่องที่ยังไม่มีในเอกสารทั้งหมด — ผมเพิ่มให้

### 4.1 🔴 PDPA — พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล

ระบบเก็บชื่อ เบอร์โทร ที่อยู่ และ (ในใบกำกับภาษี) เลขประจำตัวประชาชนของลูกค้า → เข้าข่าย PDPA เต็ม ๆ

ต้องมี: ฐานทางกฎหมายในการเก็บ · แจ้งวัตถุประสงค์ · สิทธิ์ขอดู/แก้/ลบ · ระยะเวลาเก็บ ·
log การเข้าถึงข้อมูลส่วนบุคคล · ข้อตกลงกับผู้ให้บริการคลาวด์

ทำตั้งแต่ออกแบบถูกกว่าแก้ทีหลังมาก

### 4.2 🔴 e-Tax Invoice — ต้องตัดสินใจก่อนออกแบบเอกสาร

ถ้าจะออกใบกำกับภาษีอิเล็กทรอนิกส์ตามระบบสรรพากร ต้องมีใบรับรองอิเล็กทรอนิกส์และผู้ให้บริการ
ซึ่งกระทบทั้งรูปแบบเอกสาร การเก็บ และการนำส่ง — **ตัดสินใจทีหลังแล้วต้องรื้อ**

### 4.3 🔴 สำรองข้อมูลและกู้คืน

ระบบเดียวของทั้งกิจการ 3 สาขา ถ้าข้อมูลหายคือหยุดธุรกิจ
ต้องมีแผนสำรองอัตโนมัติ + **ทดสอบกู้คืนจริงอย่างน้อยปีละครั้ง**

### 4.4 🟠 เน็ตร้านล่ม

ร้านต่างจังหวัดเน็ตไม่นิ่ง — ต้องออกแบบให้อย่างน้อย **บอกชัดเจนว่ายังบันทึกไม่สำเร็จ**
ไม่ใช่ให้พนักงานคิดว่าบันทึกแล้วทั้งที่ยัง

### 4.5 🟠 พ.ร.บ. / ประกันภัย ควรเป็นกรมธรรม์ ไม่ใช่ของแถม

ตอนนี้ พ.ร.บ. เป็นแค่รายการของแถมราคา 320 บาท
แต่จริง ๆ คือกรมธรรม์ที่**มีวันหมดอายุ** และต้องต่อทุกปี → เป็นรายได้ซ้ำที่ระบบควรเตือนให้

### 4.6 🟠 LINE — ช่องทางแจ้งเตือนที่เหมาะที่สุด

deck เขียนเองว่าอยากได้ LINE broadcast list สำหรับเตือนเช็กระยะ
LINE ถูกกว่า SMS มากและคนไทยใช้ทุกคน — ควรวางไว้ในสถาปัตยกรรมตั้งแต่แรก

### 4.7 🟠 สีแดงถูกใช้สองความหมายพร้อมกัน

ใน v0.5 สีแดงเป็นทั้ง**สีแบรนด์** (ปุ่มหลัก เมนูที่เลือก) และ**สีผิดพลาด** (ค่าติดลบ ของหมด)
ส่วนสี "ดี" กลับเป็นน้ำเงิน ซึ่งขัดสัญชาตญาณ

พอเปลี่ยนเป็นสีแดงยามาฮ่าเป็นสีหลัก ยิ่งต้องแยกให้ชัด → แก้แล้วใน `04-design-system.md`

### 4.8 🟠 ตารางราคาต้องมีวันที่เริ่มใช้

ข้อมูลจริงพิสูจน์แล้วว่า **8 จาก 50 คันหาราคาขายไม่ได้** เพราะรหัสรุ่นไม่มีในตารางราคา 5 มี.ค. 2569
ยามาฮ่าออกรุ่นใหม่ตลอด → ตารางราคาต้องเก็บได้หลายรุ่นพร้อมวันที่มีผล ไม่ใช่ตารางเดียวตายตัว
