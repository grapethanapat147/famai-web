## 2. ค้นพบสำคัญ — `รหัสผลิตภัณฑ์` เชื่อมกับตารางราคายามาฮ่าได้

```
รหัสผลิตภัณฑ์ (10 ตัว)  =  แบบรถ (6 ตัว)  +  รหัสสี (4 ตัว)
    BTF200010E          =     BTF200       +      010E
```

และ **`010A`–`010F` คือหัวคอลัมน์สีในตารางราคายามาฮ่า** (`reference/deck/yamaha-price-list-2569-03-05.png`) พอดี

ตรวจสอบแล้วตรงกันทุกคู่ เช่น

| SKU ในไฟล์ | สีในไฟล์ | ตารางราคา |
|---|---|---|
| `BTF200` + `010E` | แดง | BTF200 คอลัมน์ 010E = แดง ✅ |
| `D18100` + `010C` | เทา | D18100 คอลัมน์ 010C = เทา ✅ |
| `D18100` + `010D` | น้ำตาล | D18100 คอลัมน์ 010D = น้ำตาล ✅ |
| `BJKC00` + `010B` | ดำ | BJKC00 คอลัมน์ 010B = ดำ ✅ |

**ผลที่ได้:** ระบบสามารถดึง **ราคาขายปลีกแนะนำ · รุ่นปี · ซีซี · ประเภท (Sport/Automatic/Moped)** จากตารางราคาได้อัตโนมัติ
โดยไม่ต้องให้คนกรอก — แค่ join ด้วย `แบบรถ`

> โปรโตไทป์ v0.5 เขียนหมายเหตุไว้ว่า *"ไฟล์ยามาฮ่าไม่มีช่องนี้ ต้องกรอกเอง"* สำหรับปีรถ
> **จริง ๆ แล้วไม่ต้องกรอก** — ดึงจากตารางราคาผ่าน `แบบรถ` ได้เลย

**ยืนยันความถูกต้อง:** ต้นทุนใน `.xls` ตรงกับตารางราคา **42/42 แถวที่หาเจอ ไม่ผิดสักแถว**

## 3. ปัญหาคุณภาพข้อมูล — ต้องจัดการตอน import

### 3.1 🔴 ไฟล์ไม่ได้บอกชื่อสาขาจริง

`DOC_BRANCH_NAME` และ `ชื่อที่เก็บ` เป็น **`สำนักงานใหญ่` ทั้ง 50 แถว** ทั้งที่มาจาก 3 สาขาต่างกัน
→ ชื่อสาขาต้องมาจาก **ตารางสาขาในระบบเรา** โดย map จาก `DOC_BRANCH_CODE` เท่านั้น

**และห้ามเดาสาขาจาก prefix ของเลขเอกสาร** — มันไม่ตรงกัน:

| `DOC_BRANCH_CODE` | prefix ใน `เลขที่รับ` / `เลขที่เอกสาร` |
|---|---|
| FMG01 | `SMG01` ❌ ไม่ตรง |
| FCG01 | `FMG01` ❌ ไม่ตรง (ไปชนกับรหัสอีกสาขา!) |
| FMM01 | `FMM01` ✅ ตรง |

FCG01 ใช้ prefix `FMG01` ซึ่งเป็นรหัสของอีกสาขาหนึ่ง — ถ้าเขียนโค้ดตัด prefix มาใช้ **ข้อมูลจะเข้าผิดสาขาทันที**

### 3.2 🔴 เลข 0 นำหน้าหายเป็นบางไฟล์

Excel เก็บบางช่องเป็นตัวเลข บางช่องเป็นข้อความ — **ค่าเดียวกันแต่คนละชนิด**

| คอลัมน์ | ไฟล์ที่เป็นข้อความ | ไฟล์ที่เป็นตัวเลข |
|---|---|---|
| `รหัสสี` | `0100` `0200` `0300` `0500` `0700` | `100` `200` `300` `500` `700` |
| `TAXID` | `0105507000645` (33 แถว) | `105507000645` (17 แถว) |

ทั้ง 5 รหัสสีที่ชนกัน คือ **สีเดียวกันเป๊ะ** (100=แดง, 200=น้ำเงิน, 300=ดำ, 500=ฟ้า, 700=เทา)
→ ถ้า import ตรง ๆ จะได้ **สีซ้ำซ้อน 5 คู่** ในฐานข้อมูล

**วิธีแก้:** normalize ทุกรหัสเป็นข้อความแล้วเติม 0 ให้ครบ 4 หลัก (`padStart(4,'0')`) ก่อนบันทึก
เฉพาะไฟล์ `110967fg.xls` (ไฟล์เก่าสุด ปี 2024) ที่เป็นตัวเลขทั้งไฟล์ — ไฟล์ปี 2026 เป็นข้อความหมดแล้ว

### 3.3 🟠 `รหัสที่เก็บ` ใช้การไม่ได้

5 ค่าใน 5 ไฟล์ — คนละแบบทุกไฟล์:

| ไฟล์ | ค่า |
|---|---|
| `110967fg.xls` | `0` และ `26` (ตัวเลข) |
| `020469fmm.xls` | `0028` |
| `fg220769.xls` | `00026` |
| `fmm220769.xls` | `0028` |
| `fcg250769.xls` | **`สำนักงานใหญ่`** ← ชื่อไทยอยู่ในช่องรหัส |

`26` กับ `00026` คือที่เก็บเดียวกันแต่เติม 0 ไม่เท่ากัน และไฟล์หนึ่งใส่ชื่อแทนรหัสไปเลย
→ **อย่าใช้คอลัมน์นี้** ให้ใช้ `DOC_BRANCH_CODE` แทน

### 3.4 🟠 วันที่ในไฟล์ปี 2024 น่าจะสลับวัน/เดือน

ใน `110967fg.xls`:

| ช่อง | ค่า |
|---|---|
| `วันที่ใบรับ` | 2024-**09-11** (11 ก.ย.) |
| `วันที่เอกสาร` / `วันที่ใบกำกับภาษี` | 2024-**11-09** (9 พ.ย.) |
| `REPORT_DATE_START` / `STOP` | 2024-**11-09** |
| วันที่สร้างไฟล์ (metadata) | **11 ก.ย. 2024** |
| ชื่อไฟล์ `110967` | 11/09/67 → **11 ก.ย. 2567** |

ไฟล์ถูกสร้างวันที่ 11 ก.ย. 2024 แต่ช่วงเวลาของรายงานกลับเป็น 9 พ.ย. 2024 — **ซึ่งยังมาไม่ถึงตอนสร้างไฟล์**
เป็นอาการคลาสสิกของการอ่านวันที่ไทย `11/09` ด้วย locale อเมริกัน (กลายเป็นเดือน 11 วันที่ 9)

สังเกตว่าไฟล์ปี 2026 ทุกไฟล์มีวันที่ ≥ 20 จึงสลับไม่ได้ และค่าตรงกันหมด — **ปัญหาจึงโผล่เฉพาะเมื่อวันและเดือนต่างก็ ≤ 12**

> ⚠️ **ต้องยืนยันกับฝ่ายที่ออกรายงาน** ว่าใบจัดซื้อชุดนั้นลงวันที่ 11 ก.ย. หรือ 9 พ.ย.
> ถ้า import โดยไม่ตรวจ รถ 17 คันจะถูกลงวันที่ผิดไป 2 เดือน
> **ทางที่ปลอดภัยคือใช้ `วันที่ใบรับ` เป็นหลักเสมอ** (ค่าถูกต้องในทุกไฟล์)

### 3.5 🟠 8 คันหาราคาขายไม่ได้

`แบบรถ` 3 รหัสนี้ **ไม่มีในตารางราคา 5 มี.ค. 2569**:

| รุ่น | แบบรถ | ต้นทุน | จำนวน |
|---|---|---|---|
| FINN | `DA6200` | 42,000 | 5 คัน |
| Grand Filano Hybrid | `BJKE00` | 64,600 | 2 คัน |
| Aerox | `D13100` | 84,100 | 1 คัน |
| | | | **8 คัน** |

นี่คือสาเหตุที่ prototype v0.5 มีรถ **8 คันที่ราคาขายเป็นค่าว่าง** และต้องเดาเป็น `ต้นทุน + 15%` — ตรงกันพอดี

**วิธีแก้:** ตารางราคาต้องเป็น **master ที่มีวันที่เริ่มใช้** เก็บได้หลายรุ่นราคา
